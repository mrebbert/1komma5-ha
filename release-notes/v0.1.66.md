Internal-only release. No entity, service or blueprint behaviour change; existing automations continue to work with the same schema.

## Changed

**SDK pin bumped to `onekommafive>=1.1.3,<2`** (from `>=1.0.3,<2`). Home Assistant installs the new SDK on first reload after the update; no manual step required. The v1.1 line continues the async aiohttp surface with `py.typed`, so the integration keeps its `mypy --strict` clean stance. The bump also captures an upstream API alignment: `System.get_optimizations(start, end)` now sends `view=historic` (v1.1.1) in anticipation of the 1KOMMA5° endpoint enforcing that parameter; without it, once enforcement lands, the response would collapse to an empty `events` list without a warning. As of 2026-09-28 the endpoint still returns identical payloads with and without the parameter, so no existing install currently sees a regression; the bump is a proactive guardrail. v1.1.1 additionally introduces `System.get_live_optimizations()` for the currently running optimisation slot; the integration itself does not consume it yet. v1.1.2 exposes four new `module1_*` fields on `HeartbeatAiSummary` (provisioning date, active days, per-year / total net savings), which v1.1.3 documents as the working hypothesis "§14a EnWG Modul 1 grid-fee reduction" (API value is net; the tariff area's published gross is roughly 1.19 × the API figure, based on the first observed account). The integration does not currently consume `get_heartbeat_ai_summary`.

**Ruff line-length lowered from 100 to 88.** The Home Assistant core Ruff config uses 88; aligning removes the last non-default choice in the repo's style stack. `ruff format` reformatted 54 files (193 lines rewrapped automatically) plus 41 manual cleanups (docstring trims, inline-comment relocations, a couple of factored-out f-strings and long test-fixture lines). No entity or code-path behaviour changed.

**`.git-blame-ignore-revs` added.** The two reformat commits (config switch + manual cleanups) are recorded so `git blame` continues to point at the substantive authors of each line. GitHub honours the file automatically; contributors enable it locally once with `git config blame.ignoreRevsFile .git-blame-ignore-revs`. `CONTRIBUTING.md` gains a short "Ignoring reformat commits in `git blame`" section.

**Example dashboards restructured for multi-EV assignments.** `dashboard/dashboard.yaml` and `dashboard/dashboard-showcase.yaml` now stack the Fahrzeug view as *Wallbox → Fahrzeug* → *Lademodus* → *Smart-Charge Einstellungen*, with per-EV conditional blocks that follow the currently-assigned vehicle. Placeholders switch from `CAR_IDENTIFIER` to `EV_N_PREFIX` / `EV_N_SLUG`, one duplication per EV. The Fahrzeug screenshot in `dashboard/README.md` and the placeholder table there are updated accordingly. Also fixes a latent Smart-Charge-visibility bug (the previous condition compared the read-only `sensor.…_lademodus` uppercase state against a lowercase value; the new blocks compare against the `select.…_lademodus` state).
