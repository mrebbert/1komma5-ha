Picks up SDK 1.2.4's new ``agreedTerms`` mapping on ``/customers/{cid}/subscriptions``: each contract now ships the revision history of its commercial terms, with the current revision marked by ``effective_until=None`` and any upcoming price change scheduled as a later revision. v0.1.78 surfaces both the history and the next planned price change as Home Assistant entities.

## Added

**New sensor ``sensor.<sys>_next_subscription_price_change``.** Diagnostic timestamp entity on the system parent. State is the ISO-timestamp of the earliest future ``effective_from`` across all ``ACTIVE`` subscriptions, or ``unknown`` when no future revision exists. The attribute dict carries ``subscription_type``, ``next_price_amount_minor``/``next_price_currency``/``next_billing_frequency`` for the upcoming revision, and ``current_price_amount_minor``/``current_price_currency`` for the revision in force right now, so a dashboard card can render "HEARTBEAT: 29.99 EUR → 34.99 EUR on 2026-12-01" without a template.

**``agreed_terms`` projection on ``sensor.<sys>_active_subscriptions``.** Each entry in the ``contracts`` attribute now carries an ``agreed_terms`` list with ``revision``, ``reason``, ``price_amount_minor``, ``price_currency``, ``billing_frequency``, ``renewal``, ``notice_period_interval``/``notice_period_number``, ``effective_from`` and ``effective_until``. Older backend responses predate the field — the SDK then returns an empty list and the attribute mirrors that as ``[]``.

## Changed

Required SDK pin bumped to ``onekommafive>=1.2.4,<2`` (manifest + pyproject). Patch-level bump that ships the ``AgreedTerm`` mapping.

## Compatibility

PII guardrail unchanged: the AgreedTerm revisions surfaced here contain only commercial terms (price, cadence, notice period, effective-from/until), no IBAN, no customer/site IDs, no terms-and-conditions document links. The existing contract fields are untouched. 469 tests green, ``mypy --strict`` clean, ``ruff`` clean, Python 3.14 + HA 2026.10.2.
