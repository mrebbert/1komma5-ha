v0.1.53 — one small addition on the daily-savings sensor. No breaking changes, no migration.

## Added

**`co2_saved_kg` attribute on `sensor.<sys>_daily_savings`.** Lifetime CO2 avoided by your site, in kilograms, sourced from `system.get_impact_overview()` (v2 endpoint added upstream in SDK 0.1.44). Fetched once at setup and exposed as a plain attribute on the existing daily-savings sensor — no new sensor, no new coordinator.

The value is a running lifetime total from the 1KOMMA5° cloud (not a daily figure). Use it in a template sensor or dashboard tile if you want a "trees planted equivalent" or "km driven equivalent" readout:

```yaml
template:
  - sensor:
      - name: "CO2 saved (trees equivalent)"
        unit_of_measurement: "trees"
        state: >
          {{ (state_attr('sensor.YOUR_SYSTEM_daily_savings', 'co2_saved_kg') | float(0) / 21) | round(0) }}
```

(21 kg of CO2 per year per average tree is a common rule of thumb.)

If the cloud endpoint fails at setup, the attribute is simply absent — no error, no `unavailable` state on the parent sensor.
