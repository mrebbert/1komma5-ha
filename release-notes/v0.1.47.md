## A productivity-focused release

v0.1.47 ships **six user-visible additions** plus a small cosmetic fix — no schema changes, no migrations, no breaking changes. Six new automation blueprints (including two added in this version), three new sensor entities, a new service for on-demand coordinator refreshes, and an option that finally lets the cheapest-charging-window sensor work for loads other than the hardcoded 60 minutes.

## Headline: configurable charging-window duration

`sensor.<sys>_cheapest_charging_window_today` previously locked in a fixed 60-minute window. If your dishwasher runs 45 minutes or your washing machine 90, the sensor was useful but never *quite* right.

Now: **Settings → Devices & Services → 1KOMMA5° → Configure** exposes a *Charging-window duration* dropdown with values from 15 to 240 minutes in 15-minute steps. The sensor re-picks immediately after a change (no HA restart needed) — and existing lock-in semantics carry over for the chosen duration.

Defaults unchanged at 60 min, so nothing changes for existing installs unless you opt in.

## On-demand coordinator refresh

New service `onekommafive.refresh_now` forces an immediate refresh of any (or all) of the five data coordinators:

```yaml
service: onekommafive.refresh_now
data:
  coordinator: all     # or live | price | optimization | weather | system_status
response_variable: result
# result == {"refreshed": ["live", "price", ...], "failed": []}
```

Useful after a power outage, for debugging, and as a reset hook in automations — instead of waiting up to an hour for the next scheduled poll.

## Two new automation blueprints

| Blueprint | What it does |
|---|---|
| `notify_negative_prices_tomorrow` | Notification when tomorrow's forecast contains at least N negative-price slots. Fires around 13:00 CET when tomorrow's prices arrive. |
| `ev_charge_on_pv_surplus` | Toggles a switch ON when home battery is full **AND** PV power exceeds a threshold, OFF when either fails. Deactivation delay smooths cloud-cover dips. |

Both live under `blueprints/automation/onekommafive/` — see [the blueprints README](https://github.com/mrebbert/1komma5-ha/blob/main/blueprints/automation/onekommafive/README.md) for import instructions.

## Three new sensor entities

Surfacing metadata the SDK already collected at setup, previously only visible in the diagnostics download:

- **`binary_sensor.<sys>_energy_trader_active`** — ON when your site is enrolled in 1KOMMA5°'s virtual power plant (energy trading).
- **`binary_sensor.<sys>_dynamic_pulse_compatible`** — ON when your site qualifies for Dynamic Pulse (dynamic-tariff optimisation).
- **`sensor.<sys>_system_age_days`** — days since `SystemDetails.earliest_measurement`. Diagnostic-categorised, advances by 1 each midnight.

## Showcase dashboard variant

New `dashboard/dashboard-showcase.yaml` — a six-view dashboard (Grid / Vehicle / Prices & costs / Optimization / Weather / System) that exercises the full integration surface. The original three-view `dashboard.yaml` stays as the compact daily-driver layout; the Showcase is the "see what's possible" option. [Dashboard README with thumbnails of all six tabs](https://github.com/mrebbert/1komma5-ha/tree/main/dashboard).

## Fixed: connectivity-sensor name duplication

Since the v0.1.44 sub-device split, per-asset connectivity binaries rendered with a duplicated noun — "Wechselrichter Wechselrichter verbunden". The four asset-type translations are now just the past-participle word ("Verbunden" / "Connected" / etc.) across all seven locales — HA composes the device name and entity name into "Wechselrichter Verbunden". `entity_id`s and `unique_id`s are unchanged.

## What you need to do

Nothing. Defaults are conservative across the board:

- Charging-window duration default stays 60 min.
- New binary sensors / system-age sensor appear automatically with sensible default visibility.
- New blueprints are opt-in (import + create automation).
- Connectivity fix is cosmetic; no automation/dashboard impact.
