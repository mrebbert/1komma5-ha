Live-regression fix on the "cheapest hour now" binary sensor plus a label refinement on the energy-trader diagnostic. Behaviour-only, no new entities, services or configuration surfaces; no change to existing automations.

## Fixed

**`binary_sensor.<sys>_cheapest_hour_now` now bounds the comparison to the next 24 hours.** The price coordinator fetches today + tomorrow (up to 30 h), so a marginally cheaper slot on the next calendar day kept the sensor stuck at OFF the whole current day. A live install observed 730 state changes without a single ON. The sensor now ignores forecast slots whose start is ≥ `now + 24h`, matching the entity's docstring. `extra_state_attributes.cheapest_slot_start` reflects the same window.

## Changed

**`binary_sensor.<sys>_energy_trader_active` label sharpened.** The display name moves from `Energiehandel aktiv` / `Energy trading active` to `Energiehandel (virtuelles Kraftwerk)` / `Energy trading (virtual power plant)`. The old label read like a feature-flag counterpart to the `active_features` list and caused confusion when the sensor was ON while `active_features` did not list "Energiehandel". The flag actually reflects enrolment in 1KOMMA5°'s virtual-power-plant programme (`SystemDetails.energy_trader_active`), a separate concept from the per-site optimisation features (Dynamic Tariff, Time-of-Use, Smart Charging). Entity ID and unique_id are unchanged; only the display name changes.

## Compatibility

Behaviour-only fix on an existing diagnostic entity. Automations that key on `binary_sensor.<sys>_cheapest_hour_now == "on"` will now actually trigger within each day's cheapest slot rather than only on days where today's minimum beats tomorrow's. The `energy_trader_active` label change is cosmetic; automations that key on the entity by its ID are not affected. `mypy --strict` clean, ruff clean.
