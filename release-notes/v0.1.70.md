Live-regression fix on the "cheapest hour now" binary sensor. Behaviour-only, no new entities, services or configuration surfaces; no change to existing automations.

## Fixed

**`binary_sensor.<sys>_cheapest_hour_now` now bounds the comparison to the next 24 hours.** The price coordinator fetches today + tomorrow (up to 30 h), so a marginally cheaper slot on the next calendar day kept the sensor stuck at OFF the whole current day. A live install observed 730 state changes without a single ON. The sensor now ignores forecast slots whose start is ≥ `now + 24h`, matching the entity's docstring. `extra_state_attributes.cheapest_slot_start` reflects the same window.

## Compatibility

Behaviour-only fix on an existing diagnostic entity. Automations that key on `binary_sensor.<sys>_cheapest_hour_now == "on"` will now actually trigger within each day's cheapest slot rather than only on days where today's minimum beats tomorrow's. `mypy --strict` clean, ruff clean.
