v0.1.49 — hardening release. No new entities, no schema changes, no migrations. Two robustness fixes only.

## Changed

**SDK pinned to `>=0.1.23,<0.2`** — Home Assistant installs the `onekommafive` requirement automatically on every install, so an unbounded pin meant a breaking SDK release could ship untested to all users. The upper bound is cheap insurance; it is raised deliberately when a new SDK minor is adopted.

## Fixed

**Coordinator fetch timeout** — every one of the six coordinators now wraps its fetch in a 30 s timeout. All SDK calls are synchronous HTTP run in the executor, and `DataUpdateCoordinator` imposes no timeout of its own, so a hung request could previously pin a coordinator (and an executor thread) indefinitely. A timeout now surfaces as a normal failed update: the affected entities go `unavailable` and the next scheduled interval retries. (The executor thread still runs until the underlying call returns — threads can't be cancelled — but the coordinator no longer hangs.)

## Upgrade

Nothing required. No `entity_id` / `unique_id` changes, no statistics impact. Purely internal robustness plus a dependency constraint.
