Hotfix for a blocking-call warning HA 2026.10 raised on the System Information panel. Behaviour-only, no new entities, services or configuration surfaces; no change to existing automations.

## Fixed

**`system_health` no longer blocks the event loop on `importlib.metadata`.** The System Information panel used to call `helpers.sdk_version()` synchronously on every render, which traverses `site-packages` via `listdir` + `open` + `read_text` on the dist-info `METADATA` file. On HA 2026.10 this surfaces as three repeated blocking-call warnings in the log. Setup already resolves the SDK version in an executor at config-entry load; the panel now reads that cached value from `runtime_data` instead. An executor-based fallback via `async_add_executor_job` stays in place for the edge case where System Health is queried before any config entry finishes setup, so the panel still populates `sdk_version` (or `"unknown"`) in that window.

## Compatibility

Behaviour-only. `mypy --strict` clean, ruff clean, 410 tests green. The warning in `home-assistant.log` disappears after upgrading; no action required by users.
