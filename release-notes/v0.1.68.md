## Changed

**SDK pin bumped to `onekommafive>=1.1.7,<2`** (from `>=1.1.6,<2`). Home Assistant installs the new SDK on first reload after the update; no manual step required. v1.1.7 adds `Notification.updated_at: str | None` — the ISO-8601 timestamp of the last read/dismissed state change on `/users/{uid}/notifications/latest`. Additive, `None` on notifications that have never changed state after creation. The notifications-coordinator payload keeps its existing shape; the new field flows through the `onekommafive_notification` bus event for anyone who wants to key on it.

**Config-flow login diagnostics.** When the credentials step fails, the integration now writes a WARNING line with the SDK's error context (`1KOMMA5° authentication failed: …` or `1KOMMA5° request failed during login: …`). Previously only the opening `Starting OAuth2 PKCE login` DEBUG line surfaced, which made it hard to separate "wrong credentials" from "account not in the mobile-app Auth0 tenant" or "network error". The user-facing form still shows the generic `invalid_auth` / `cannot_connect` label; the new WARNING is for operators and issue reports.
