v0.1.59: bugfix release. Prevents the last-optimization-decision sensor from crashing when the 1KOMMA5° Cloud ships a new decision value it hasn't seen before.

## Fixed

**`sensor.<sys>_optimization_last_decision` survives unknown cloud values.** The 1KOMMA5° Cloud started shipping `EV_CHARGE_FROM_GRID` as a new AI-optimization decision on 2026-09-11. HA's ENUM-sensor validation rejected the value because it wasn't in the sensor's static options list, and the sensor raised `ValueError: … not in the list of options provided` on every 15-minute refresh cycle.

Two-part fix: `EV_CHARGE_FROM_GRID` is now a known option (state shows through normally), and the sensor coerces any future unknown decision to `unknown` plus one log warning naming the new value. So the next new cloud enum value shows up in your log as "extend the sensor to surface it" instead of crashing the sensor.

Automations that gate on `state == "battery_charge_from_grid"` etc. keep working unchanged. If you want to react to the new `ev_charge_from_grid` decision, add it to your automation trigger.

## Changed

**SDK pin raised to `onekommafive>=0.3.0,<0.4`.** Upstream v0.3.0 is a KISS-cleanup release (CLI restructure, deduplicated subcommand bodies, hoisted test fixtures, tighter docstrings). No public API change: no new endpoint, no removed field, no signature change. The major-bump reflects the cleanup cut, not a break; the integration itself needs no code change.
