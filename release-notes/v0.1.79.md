Picks up SDK 1.4.0, which routes through the BFF gateway by default. The vendor's web app routes every heartbeat and identity call through the single BFF host ``heartbeat-bff.1komma5grad.com`` since 2026-11. v0.1.79 follows: both the runtime client in ``__init__.py`` and the validation client in the config flow use the SDK default.

## Changed

**API host routing is now the BFF gateway.** The SDK rewrites each call path at request time: ``heartbeat.1komma5grad.com/api/v1/...`` becomes ``heartbeat-bff.1komma5grad.com/heartbeat/v1/...``, likewise for the identity host. Semantics stay the same; the change buys alignment with the vendor's web app and shields the integration from a future shutdown of the per-service hosts.

**Required SDK pin bumped to ``onekommafive>=1.4.0,<2``** (manifest + pyproject).

## Compatibility

Set ``ONEKOMMAFIVE_GATEWAY=direct`` in the Home Assistant process environment to revert to the per-service hosts without a code change; the SDK reads the variable on client construction. Entity IDs, ``unique_id``s, options-flow fields and the OAuth2 token cache are untouched. 469 tests green, ``mypy --strict`` clean, ``ruff`` clean, Python 3.14 + HA 2026.10.2.
