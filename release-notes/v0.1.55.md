v0.1.55 — hotfix for the intermittent "Validation failed" error on the market-prices endpoint. No behavioural changes elsewhere.

## Fixed

**Intermittent price-refresh failure.** If you saw log entries like

```
ERROR ... Error fetching 1KOMMA5° Prices data: API error fetching price data:
Failed to get prices: {"error_code":100006, "correlation_id":"…",
"message":"ApiClientForwardedException: Validation failed"}
```

they are gone with this release.

The 1KOMMA5° v4 market-prices endpoint recently started rejecting `from` / `to` query params that don't land on the resolution grid (15-min slots for the default `resolution=15m`). The integration was sending `to=YYYY-MM-DDT23:59:59Z`, which no longer aligns — so a fraction of hourly refreshes ended up as `HTTP 422 Validation failed`.

Upstream SDK 0.1.47 fixes this by snapping `from` down and `to` up to the resolution grid before the request. This release just bumps the pin to `onekommafive>=0.1.47,<0.2`; no HA-side code change needed.

## Not affected

The `stable_electricity_price` sensor already held the last valid value across these transient errors, so cost accumulation kept running through them. Nothing to reset or backfill manually.
