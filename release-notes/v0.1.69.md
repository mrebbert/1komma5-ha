Authoritative §14a readout plus config-flow diagnostic refinement. One new diagnostic entity and two new attributes on the existing §14a sensors; no change to existing automations.

## Added

**`sensor.<meter>_enwg14a_module`** — ENUM diagnostic on the meter sub-device. States: `none` (not enrolled), `module_1` (BK6-22-300 pauschale Reduktion), `module_3` (variable HT/NT), `unknown` (site-info fetch failed or returned an unmapped slug). Backed by SDK v1.1.8's `SiteSystemInfo.enwg14a_module` from the dedicated `/api/v1/sites/{id}/system-info` endpoint. The pre-existing `module1_grid_fee_reduction_annual` and `module3_grid_fee_savings_annual` sensors continue to infer §14a enrolment from heartbeat-window fields; the new sensor is the authoritative, separately-fetched readout.

## Changed

**Two new attributes on the existing §14a sensors.** Both now carry `enwg14a_module_valid_from` (ISO-8601 date from the authoritative endpoint) for traceability. The Modul-3 sensor additionally surfaces `variable_grid_fee_eur_per_kwh` as the HT/NT counterpart to the already-exposed `comparison_grid_fee_eur_per_kwh`.

**SDK pin bumped to `onekommafive>=1.1.8,<2`** (from `>=1.1.7,<2`). v1.1.8 adds `/api/v1/sites/{id}/system-info` as `SiteSystemInfo(availability, enwg14a_module)` and the `variable_grid_fee_eur_per_kwh` per-window field consumed above.

**Shorter config-flow failure WARNING line.** v0.1.68 added a WARNING with the SDK's raw error context, which turned out to include the full Auth0 Universal Login HTML page (~68 KB) when step 2 of the OAuth2/PKCE login rejects credentials. v0.1.69 now reduces that body to its `<title>` plus the byte count — e.g. `Login failed: 1KOMMA5° Sign-in [HTML body suppressed, 68123 bytes]`. Non-HTML bodies above 300 characters are clipped with a `[truncated, N bytes total]` tag. Messages without the `<label>: <body>` shape pass through unchanged. The user-facing form still shows the generic `invalid_auth` / `cannot_connect` label.

## Compatibility

Additive. The authoritative `enwg14a_module` sensor is diagnostic and defaults to visible; existing automations keying off `module1_grid_fee_reduction_annual` / `module3_grid_fee_savings_annual` are untouched. `mypy --strict` clean, ruff clean.
