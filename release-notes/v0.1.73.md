A new aggregated AI-decisions calendar makes the 15-minute optimization timeline navigable in Lovelace and the HA mobile app. One new entity, no breaking changes.

## Added

**`calendar.<sys>_ai_decisions_calendar`** — a Home Assistant calendar entity on the system parent device that renders AI decisions as time-blocks across any date range. Lovelace calendar cards, the mobile-app calendar view and HA's native `calendar.get_events` service all work without extra configuration.

For the past, the entity reconstructs decision blocks from the Recorder history of the six existing `optimization_*` binary sensors. Contiguous `on`-slots of the same decision collapse into one event with the full phase span — a four-slot `BATTERY_NO_CHARGE` run shows as a single hour-long block, not four 15-minute rectangles. Historical reach follows your Recorder retention (10 days by default).

For the future, a price-based proxy surfaces blocks derived from the price-coordinator forecast (next 30 h). Slots below the 33rd percentile mark expected `EV_CHARGE_FROM_GRID` windows; slots above the 67th percentile mark expected `BATTERY_DISCHARGE_TO_GRID` windows. Each proxy summary is explicitly labelled "Price proxy: …" so it never masquerades as an actual AI decision. Single-slot blocks shorter than 30 minutes are suppressed as noise.

The boundary between historical and proxy events is the current UTC instant: history runs up to it, proxy starts from it. Nothing overlaps.

**New blueprint `ai_decision_calendar_trigger.yaml`** — universal calendar-driven trigger. Pick one of the eight event classes (six AI decisions + `proxy_cheap` / `proxy_expensive`), choose `start` or `end`, add an optional offset (±60 min) and plug in any action. Match uses the event's stable `description` key, so the blueprint keeps working regardless of HA UI language.

Each `CalendarEvent` now carries a stable machine-readable key in `description` (e.g. `optimization_ev_grid_charge`, `proxy_cheap`) alongside the localized `summary` for display. Existing automations keyed on `summary` continue to work; new blueprints should prefer `description` for language-independence.

## Compatibility

Additive — all existing entities, unique_ids and services stay as they are. The entity is enabled by default. Automations that iterate `calendar.get_events` see history for retained days plus 30 h of proxy events. The proxy is marketed clearly as a price-derived hint, not a backend forecast (the 1KOMMA5° API has no decision-forecast endpoint). `mypy --strict` clean, ruff clean, Python 3.14 + HA 2026.10.2.
