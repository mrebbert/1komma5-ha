Picks up SDK 1.4.0, which routes through the BFF gateway ``heartbeat-bff.1komma5grad.com`` by default, the route the vendor's web app uses. Both the runtime client in ``__init__.py`` and the validation client in the config flow now use the SDK default instead of passing ``gateway="bff"``.

## Changed

**Client routing follows the SDK default.** Requests keep going to ``heartbeat-bff.1komma5grad.com``; the integration no longer pins the choice itself.

**``ONEKOMMAFIVE_GATEWAY=direct`` works as documented.** The explicit ``gateway="bff"`` argument in v0.1.79 took precedence over the environment variable. With the SDK default, the variable reverts to the per-service hosts again.

**Required SDK pin bumped to ``onekommafive>=1.4.0,<2``** (manifest + pyproject).

## Compatibility

Entity IDs, ``unique_id``s, options-flow fields and the OAuth2 token cache are untouched. Home Assistant installs the new SDK on first reload after the update; no manual step required.
