Price sensors recover faster when the 1KOMMA5° API fails a single request. Both fixes target the price coordinator, which refreshes hourly.

## Fixed

**Price sensors no longer wait an hour after a failed first fetch.** When the API times out while Home Assistant starts, the price entities used to stay ``unavailable`` until the next hourly refresh. A coordinator without data now retries after 5 minutes; the regular interval resumes with the first successful fetch.

**Tomorrow's prices arrive as soon as they are published.** EPEX publishes the day-ahead prices at 12:00 UTC. If the fetch for tomorrow failed or returned nothing, the forecast stayed on today's slots until the next hourly refresh. From 12:00 UTC on, the price coordinator now re-polls every 10 minutes until tomorrow's slots are present, then returns to the hourly cadence. A failed fetch for tomorrow logs its error at debug level.

## Compatibility

Entity IDs, ``unique_id``s and options-flow fields are untouched. No manual step required.
