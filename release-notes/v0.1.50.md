v0.1.50 — dashboard-fix release. One user-visible fix (issue #8) plus the dashboard templates rewritten to match. No entity contract change for existing installs; fresh installs get stable, language-independent `entity_id`s.

## Fixed

**Fresh-install `entity_id`s are now stable** — every entity registers as `<platform>.<system_slug>_<code_suffix>` on new installs, regardless of Home Assistant's UI language and regardless of whether the entity is parented on the system parent or on a per-asset sub-device (inverter / heat pump / meter / wallbox / vehicle). Before this fix HA composed sub-device `entity_id`s as `<device_slug>_<entity_slug>` from the **translated** device name — so a German fresh install landed on `binary_sensor.wechselrichter_verbunden` while an English install landed on `binary_sensor.inverter_connected`, and the shipped `dashboard/dashboard.yaml` `SYSTEM_NAME` placeholder covered neither case. Fixes [#8](https://github.com/mrebbert/1komma5-ha/issues/8).

## Changed

**Dashboards use the new stable code suffixes.** `dashboard/dashboard.yaml` and `dashboard/dashboard-showcase.yaml` now reference `_pv_power`, `_heat_pumps_power`, `_electricity_cost`, `_feed_in_revenue`, `_diag_live_update`, `_cheap_electricity`, … — English code keys instead of the previous DE-translated slugs. On a fresh install replacing `SYSTEM_NAME` alone is enough for any HA language.

## Upgrade

**Existing installs: no automatic change.** Home Assistant's entity registry looks up entries by `unique_id`, which was never changed, so every one of your `entity_id`s stays exactly as it was. Long-term statistics, automations, Energy Dashboard configuration and any dashboard cards you customized keep working with no migration.

**To adopt the new stable naming on an existing install** (e.g. so the shipped `dashboard.yaml` templates work out of the box) — rename each entity manually under **Settings → Devices & Services → 1KOMMA5° → Entities**. Opt-in only; there is no automatic rewrite because that would break existing dashboards, automations and statistics. Alternative: sed the code suffixes in the dashboard YAML back to whatever your registry actually holds — see the migration note in `dashboard/README.md`.
