v0.1.65 lands two stories in one release: the wallbox → vehicle assignment surface armed as v0.1.63 (never tagged, rolled forward here) and the async SDK v1.0.2 migration that makes the integration fully non-blocking.

## Added

**`select.<sys>_<wallbox>_assigned_vehicle`** — one select entity per physical wallbox, parented on the wallbox sub-device. Options are the site's vehicle profiles (e.g. `bmw_i3`, `tesla_model_y`); the state reflects `Wallbox.assigned_ev_id`. Selecting an option calls the 1KOMMA5° API's assignment endpoint. 1KOMMA5° is 1:1 exclusive: setting one vehicle automatically releases whichever vehicle was previously bound to the same wallbox — a single call does both sides. Single-vehicle sites see the entity but have nothing to switch (no UI breakage, just an inert control).

**Service `onekommafive.assign_ev_to_wallbox`** — id-addressed counterpart to the select for automations that carry the vehicle and wallbox as data rather than as an entity slug. Schema: `wallbox_id`, `ev_id` (both required). Returns `{success, previous_ev_id}` so automations can log the swap. Rejects unknown ids with a clear `HomeAssistantError`.

**Blueprint `vehicle_at_wallbox.yaml`** — one automation per vehicle. Trigger = the vehicle's plug-in binary sensor (from a car integration or a smart-plug helper) flips to `on`; action = the wallbox's assignment select is set to that vehicle. Turns "car plugs in" into "1KOMMA5° binds the right profile" without hand-crafting the automation.

**EV view in the example dashboards gains a *Wallbox → Fahrzeug* card.** `dashboard/dashboard.yaml` and `dashboard/dashboard-showcase.yaml` reference the new select using the same placeholder convention as the rest of the file.

## Fixed

**`sensor.<sys>_optimization_event_count` counts 15-minute slots, not event objects.** The `/heartbeat-ai/optimizations` endpoint aggregates consecutive same-decision slots within a one-hour bucket into a single event object. Counting objects silently under-reported the day's decision volume by up to a factor of four. The sensor now sums `OptimizationEvent.slot_count` across events. Expect a one-time step up on the first refresh after the update: the new value is correct, the previous one was too low.

**`binary_sensor.<sys>_optimization_battery_grid_charge` and `binary_sensor.<sys>_heatpump_recommendation` stay on for the full slot span.** These sensors previously flipped back to `off` at the 15-minute mark of an aggregated hour-long decision, because the active-window check compared against `to_time` (first slot only). Now they use `end_time` (aggregated span end), so a 60-minute `BATTERY_CHARGE_FROM_GRID` decision reads as on for the full hour.

## Changed

**Every 1KOMMA5° API call runs on Home Assistant's aiohttp loop.** The previous `hass.async_add_executor_job` wraps around SDK calls are gone; the seven data coordinators, both service handlers, the four write-path platforms (switch, select, number, time), the diagnostics dump and the config-flow authentication path all `await` the SDK directly. `Detected blocking call` warnings for `onekommafive` disappear from the log.

**Shared aiohttp session with Home Assistant.** The SDK's `Client` accepts a `session=` parameter as of v1.0.2; setup passes `homeassistant.helpers.aiohttp_client.async_get_clientsession(hass)` so a single connection pool serves both HA and the 1KOMMA5° API. One less socket-set to worry about, and HA's own connection-pool lifecycle carries the SDK too.

**First-class DP price-guarantee endpoint.** Setup uses the SDK's `system.get_price_guarantee(customer_id)` directly instead of iterating the subscriptions list looking for a `DYNAMIC_PULSE` entry. `sensor.<sys>_dynamic_pulse_price_guarantee` behaves identically; the code path is one endpoint round-trip instead of a list scan.

**Static typing across the SDK boundary.** The `onekommafive` SDK ships `py.typed` since v1.0.2. The integration's runtime data container and per-coordinator dataclasses (`OneKomma5Data`, `LiveData`, `PriceData`, `SystemStatusData`, `OptimizationData`, `NotificationsData`, `EnergyTodayData`, `WeatherData`) now carry concrete SDK types (`System`, `LiveOverview`, `EVCharger`, `Wallbox`, `Asset`, `MarketPrices`, `OptimizationEvent`, `Notification`, `EmsSettings`, `EnergyData`, `SystemDetails`, `DeviceGateway`). Mypy runs clean across the integration.

**Live-coordinator wallbox fetch.** The 30-second `live_coordinator` now also carries the wallbox inventory with live `assigned_ev_id`; App→HA assignment changes surface within one tick instead of five minutes. Replaces the fetch that had briefly lived in the `system_status_coordinator`.

**Attribute additions on the optimization sensors.** `attributes.to` on `sensor.<sys>_optimization_last_decision` and on the `decisions[]` entries under `sensor.<sys>_optimization_event_count` now reflects the aggregated slot-span end. A new `slot_count` attribute exposes how many 15-min slots the decision covers. Bus event `onekommafive_optimization_decision` gains `end` (aggregated span end) and `slot_count` alongside the existing `to` (first-slot end, kept for compatibility).

## Compatibility

**SDK pin bumped to `onekommafive>=1.0.3,<2`** (from `>=0.5.0,<0.6`). Home Assistant installs the new SDK on first reload after the update; no manual step required.

No user-visible entity, service, blueprint or dashboard behaviour change from the async migration itself. Existing automations that call `onekommafive.assign_ev_to_wallbox`, `onekommafive.refresh_now`, `onekommafive.get_cheapest_window`, `onekommafive.get_most_expensive_window` or `onekommafive.get_heartbeat_metrics` continue to work with the same schema and response shape.

## Under the hood

- The base data coordinator's `_fetch` is `async def` and cooperatively cancels on `asyncio.timeout`. A stalled fetch is now actually cancelled at the 30-second mark instead of orphaning an executor thread.
- The 29 duplicated `_setup_entry` helpers moved into a shared `conftest.py` fixture (`setup_integration`), tightening the integration-test surface.
- **Test coverage lifted from 93 % to 95.4 %** (292 tests, +25 new). CI now enforces `--cov-fail-under=95`; `helpers.py`, `system_health.py` and `diagnostics.py` reach 100 %. Closes the Quality-Scale `test-coverage` vorbehalt.
- **`mypy --strict` is now the default.** `pyproject.toml [tool.mypy] strict = true`. The eleven remaining strict errors were resolved with typed generics, explicit `bool` / `float | None` casts on entity properties, and two `# type: ignore[attr-defined]` markers for HA modules that re-export symbols via `__init__` but not `__all__`. Closes the Quality-Scale `strict-typing` vorbehalt.
