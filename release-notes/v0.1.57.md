v0.1.57 — clearer diagnostics for the two 1KOMMA5° backend architectures. No behavioural changes to any sensor.

## Changed

**Diagnostics: better triage for missing wallbox controls.** 1KOMMA5° installs come in two flavours, and it matters when the charging-mode / target-SoC / departure-time entities don't appear:

- `emp_type == "GRIDX"` — classic model with a local DeviceGateway (the GridX box). All wallbox and EMS SDK endpoints work; missing controls usually mean a vehicle profile isn't paired to the wallbox in the 1KOMMA5° app.
- `emp_type == "1K5"` — newer 1k5-native cloud EMS without a DeviceGateway. Live values, prices and optimizations still work, but every wallbox / EMS endpoint hits `error_code:30401 "DeviceGateway not found"`. The message is literally correct (no DeviceGateway exists) but it reads like a setup bug when it's actually the architecture — 1KOMMA5° routes these installs via a backend path the SDK doesn't yet cover.

The `system.wallboxes[]` block in the diagnostics download (*Settings → Devices & Services → 1KOMMA5° → ⋮ → Download diagnostics*) now decodes this. On the 30401 error path the entry now includes:

```json
{
  "error": "RequestError('Failed to get wallboxes: {...}')",
  "emp_type": "1K5",
  "device_gateway_count": 0,
  "emp_type_1k5_native_hint": true
}
```

If `emp_type_1k5_native_hint` is `true`, the missing wallbox-control entities are the architecture — nothing to fix in the integration or in your setup for now.
