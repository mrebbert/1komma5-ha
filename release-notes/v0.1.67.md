Internal-only release: SDK pin bump. No entity, service or blueprint behaviour change; existing automations continue to work with the same schema.

## Changed

**SDK pin bumped to `onekommafive>=1.1.4,<2`** (from `>=1.1.3,<2`). Home Assistant installs the new SDK on first reload after the update; no manual step required. v1.1.4 adds `System.get_subscription_eligibility()` for the `GET /api/v1/sites/{id}/subscription-eligibility` endpoint — a list of 1KOMMA5°Care add-on products the account can purchase (`PV_SERVICE`, `MAINTENANCE_HEAT_PUMP`, …) with an `eligible` flag and a human-readable `reason` when the backend gates it. The integration does **not** consume this endpoint: it is an upsell/eligibility surface, not an operational signal, so it stays out of the HA entity catalogue by design. The bump is a straightforward floor update to keep the installed SDK current.

## Compatibility

All existing entities, services and the blueprint stay unchanged. `mypy --strict` still clean, 302 tests pass at 95.4 % coverage, ruff clean.
