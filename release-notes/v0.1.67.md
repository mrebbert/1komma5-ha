Adds three Diagnostic Sensoren that surface the account's contract overview — active packages, add-on eligibility, and the EMP backend — so dashboards can show the Vertragsübersicht without further Integration-Änderungen. Also bumps the SDK floor to the version that carries the eligibility endpoint. No change to existing automations.

## Added

**`sensor.<sys>_active_subscriptions`** — number of contracts whose `status == "ACTIVE"`. The `contracts` attribute carries the PII-safe fields of every subscription: `type`, `status`, `start_date`, `end_date`, `signed_date`, `notice_period_number`, `notice_period_interval`, `renewal`, `billing_frequency`, `price_eur`, `currency`, `payment_method`, `country_code`. The raw CRM record (`id`, `site_id`, `customer_id`, `electricity_contract_number`, `market_location_id`, `terms_and_conditions_url`, `raw`-Blob mit IBAN und Adressen) stays out by whitelist. Diagnostic category keeps the entity off the main device card.

**`sensor.<sys>_subscription_eligibility`** — number of 1KOMMA5°Care add-ons the account currently qualifies for. Attributes split the backend's response into `eligible` (list of product types) and `ineligible` (list of `{type, reason}` with the CRM-provided reason verbatim — no synthesis). Reads the SDK v1.1.4 endpoint `GET /api/v1/sites/{id}/subscription-eligibility`.

**`sensor.<sys>_emp_backend`** — ENUM diagnostic sensor exposing the account's EMP backend. Options are `gridx`, `1k5`, and `unknown` (fallback when the detail call fails or returns an unexpected value). Lowercase keys to satisfy hassfest; translations map them to the display labels "GridX" / "1KOMMA5°". Previously only visible in the diagnostics dump; now addressable from automations and dashboards.

All three sensors capture their data once at setup — subscriptions and eligibility change on contract events, not during normal runtime — mirroring the `price_guarantee` snapshot pattern. The fetches are non-fatal: a failed `get_subscriptions` or `get_subscription_eligibility` call skips its sensor and leaves the rest of the integration untouched.

## Changed

**SDK pin bumped to `onekommafive>=1.1.4,<2`** (from `>=1.1.3,<2`). Home Assistant installs the new SDK on first reload after the update; no manual step required. v1.1.4 adds `System.get_subscription_eligibility()`, the endpoint behind the new `subscription_eligibility` sensor above. Everything else on the integration side continues as before.

## Compatibility

Three new diagnostic sensors on the system parent device; all existing entities, services and the blueprint stay unchanged. `mypy --strict` still clean, 309 tests pass at 95.49 % coverage, ruff clean.
