All-in electricity prices now compose per-slot so Modul-3 variable Netzentgelte (HT/NT) feed the sensor, forecast, cheapest-window, cost accumulation and price-breakdown attributes correctly. Modul-1 sites are byte-identical to v0.1.74 — this release gets Modul-3 right before the backend switch arrives.

## Changed

**Per-slot all-in composition in the price coordinator.** Until v0.1.74 the integration consumed the pre-computed `MarketPrices.prices_with_grid_costs_and_vat` dict from the SDK as the sole truth. For sites enrolled in §14a Modul 3 the Netzentgelt (`dynamic_markup`) wanders from an annual scalar to a per-15-min-slot value — the SDK already carries both in a separate `enwg14a_grid_fee` dict. The coordinator now builds `all_in_prices` slot-by-slot from `(spot_with_vat + fixed_components_with_vat + per_slot_dynamic_with_vat)`, pulling the dynamic component from the §14a dict when it's populated and falling back to the static scalar otherwise. On Modul-1 sites the composed series is bit-identical to the SDK dict (±float jitter), so no number moves there.

**Attribute `dynamic_markup` on `sensor.<sys>_current_electricity_price` tracks the active slot.** The grid-cost breakdown previously surfaced the annual scalar; it now reflects whatever HT/NT rate the active 15-min slot carries. Modul-1 sites continue to see the scalar because the dict is empty. The `grid_costs` sum reconciles accordingly.

**Daily today-statistics now derive from the composed per-slot series.** The `average_electricity_price`, `lowest_electricity_price` and `highest_electricity_price` sensors previously read the SDK scalars (`market_prices.average/lowest/highest_price_all_in`). They now compute from `PriceData.today_average/lowest/highest`, which is the same aggregation path tomorrow's sensors have always used. Modul-1 sites get the same number because the SDK scalars already match that aggregation; Modul-3 sites get consistent today-and-tomorrow numbers that follow the slot-variable series.

## Added

**30 h forecast on `sensor.<sys>_enwg14a_grid_fee_current`.** Modul-3 sites get a `forecast` attribute parallel to the one on `current_electricity_price`: a sorted list of `{start, end, price, price_with_vat}` entries over the next 30 hours. Lovelace cards can now chart the HT/NT curve alongside the spot-price forecast. Modul-1 sites keep an empty payload — the entity stays unavailable there, as before.

**Tomorrow §14a-grid-fee series merged into `PriceData`.** `_fetch_today_and_tomorrow` now mergers tomorrow's `enwg14a_grid_fee` and `enwg14a_grid_fee_with_vat` dicts alongside the spot price merge. Before this release only today's §14a values were in the house.

## Fixed

**Cost accumulation on Modul-3 sites is correct automatically.** `stable_electricity_price` reads from the composed per-slot dict, cost sensors multiply by `stable_price()` on every 30 s live tick — the moment the composed series starts to vary HT/NT, the per-15-min-slot cost rate follows. No code change was needed on the accumulator; the composition in the coordinator is the single lever.

## Compatibility

Public contract unchanged: no new entities, no renamed `unique_id`s, no changes to services or bus events. `PriceData` gains two internal dict fields and three today-aggregate fields — these are coordinator-internal and were not part of the published surface. 466 tests green (29 new), `mypy --strict` clean, `ruff` clean, Python 3.14 + HA 2026.10.2.

Note on the SDK docstring: `MarketPrices.enwg14a_grid_fee` is annotated as "§14a Modul-1-Netzentgelt" upstream, but Modul 1 is a flat annual rebate with no per-slot component — the dict is empirically the Modul-3 per-slot series. This release treats it as Modul-3; the SDK docstring will be followed up separately.
