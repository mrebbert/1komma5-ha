v0.1.54 — FoxESS sub-device support, wallbox pairing diagnostics, and cleaner logs on HA 2026.7+. No breaking changes, no migration.

## Added

**FoxESS sub-devices.** The `inverter` sub-device now matches either the `HYBRID` asset (Sungrow and friends) **or** the `PV_SYSTEM` asset that FoxESS installs report, and a new `battery` sub-device is created for the `BATTERY` asset. FoxESS users previously saw their PV and battery entities hang on the system parent device; they now sit under proper sub-devices with the same translation pattern as inverter / heat_pump / meter / wallbox. Sungrow and single-`HYBRID` installs are unchanged.

**Wallbox pairing diagnostics.** The diagnostics download (*Settings → Devices & Services → 1KOMMA5° → ⋯ → Download diagnostics*) now includes a `system.wallboxes[]` section:

```json
"wallboxes": [
  {
    "name": "Wallbox",
    "assigned_ev_id_present": true,
    "gridx_hardware_id_present": true
  }
]
```

Booleans only, no UUIDs are leaked. This makes it easy to tell from a diagnostics file whether a vehicle profile is paired to the wallbox — a missing pairing is the most common reason the charging-mode / target-SoC / departure-time entities don't appear even though the wallbox is registered.

## Changed

**No more `via_device` deprecation warnings on HA 2026.7+.** HA 2026.7 deprecated `DeviceInfo.via_device` (identifier tuple) in favour of `via_device_id` (device_registry id string); the tuple form disappears in HA 2027.8. All 1KOMMA5° sub-device DeviceInfo objects now use `via_device_id` when running on HA ≥ 2026.7 and fall back to the tuple form on older HA. No behaviour change; unique-ids and entity-ids stay stable. Users on HA 2026.7+ will see the five `via_device`-related WARNs from `homeassistant.helpers.frame` disappear from their logs after this release.

**README: EV charger / wallbox section clarified.** The charging-mode, target-SoC, and departure-time entities model the **vehicle profile** (via the SDK's `/v1/devices/evs` endpoint) — not the wallbox hardware. If no vehicle profile is registered in the 1KOMMA5° app under *Settings → Vehicles* and paired to the wallbox, these entities are simply not created; the wallbox device still appears with connectivity + aggregate `ev_chargers_power` / `ev_charger_cost` sensors from other endpoints. If you're missing these entities, check the app's vehicles section and the new diagnostics `system.wallboxes[]` block described above.
