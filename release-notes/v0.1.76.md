Hotfix for a stale `device_class` on the §14a-Modul-3-grid-fee sensor that Home Assistant 2026.10 now rejects at setup.

## Fixed

**`sensor.<sys>_enwg14a_grid_fee_current` no longer logs a config warning.** The sensor carried `device_class="monetary"` together with `state_class="measurement"`. Home Assistant 2026.10 enforces that `monetary` only pairs with `None` or `"total"` and prints a WARNING on every setup otherwise. Monetary is for pure-currency amounts, not price-per-energy — the sibling `current_electricity_price` sensor has always used only `state_class="measurement"` with native unit `EUR/kWh` and no device class. This release aligns the §14a sensor with that pattern: device class dropped, state class and native unit unchanged. No new entity, no `unique_id` or `entity_id` churn; existing recorder statistics continue.

## Compatibility

Public contract unchanged. 466 tests green, `mypy --strict` clean, `ruff` clean, Python 3.14 + HA 2026.10.2.
