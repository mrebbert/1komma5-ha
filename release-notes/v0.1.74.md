Three focused improvements on top of v0.1.73: calendar hygiene after the skill-audit, defensive Recorder-error-handling, and a new automation blueprint for the EV departure time.

## Added

**Blueprint `ev_departure_from_calendar.yaml`** — automatically pushes the next relevant HA-calendar event into `time.<sys>_<ev>_ev_departure_time`. For commuters with shifting schedules (shift work, home-office days, business trips), the 1KOMMA5° AI then sees the correct ready-by time every morning without manual pokes.

Highlights:

- **Two triggers**: evening preplan (default 20:00) sets tomorrow's departure so the AI has the full night to plan the cheapest charging slots; morning reconfirm (default 05:00) catches calendar changes made overnight.
- **Match modes**: use a dedicated commute calendar (every event counts), or a shared calendar with a case-insensitive summary keyword filter (e.g. `#drive`, `[commute]`).
- **Home-office suppression**: an optional exclude keyword skips events whose summary or location contains it (e.g. `homeoffice`, `remote`).
- **Travel-time sensor override**: optionally wire a `sensor.*_travel_time` from `waze_travel_time` / `google_travel_time` / `here_travel_time` to use live traffic data instead of a static commute buffer.
- **Fallback**: a configurable fixed time is written on event-free days (weekend, holiday, vacation) so the AI always has a planning target.

One blueprint instance per vehicle. Import badge in the blueprints README.

## Changed

- **`custom_components/onekommafive/calendar.py` cleanup**: module and helper docstrings compressed to one line each (the DST-fall-back and slot-dominance background lives in the memory notes and release-notes/v0.1.73.md, not in every file header). Removed internal back-compat aliases `PROXY_CHEAP_SPEC_KEY` / `PROXY_EXPENSIVE_SPEC_KEY` that only ever existed within the v0.1.73 development window. Dropped the unused `_LOGGER` module constant. Net: 52 fewer lines in `calendar.py`.
- **Price-proxy summaries now localized in all seven HA locales** (da, de, en, es, fi, nl, sv) via the standard HA translation framework. The previously hardcoded DE/EN strings move to `entity.calendar.ai_decisions.state_attributes.<proxy_cheap|proxy_expensive>.name` in `strings.json` and are fetched by `_refresh_translations` alongside the existing decision labels. Users on da/es/fi/nl/sv see localized proxy summaries instead of the English fallback.

## Fixed

- **AI-decisions calendar degrades gracefully when the Recorder lookup fails**. A Recorder exception in the historical-blocks lookup used to propagate out of `async_get_events`, which also dropped the forward-looking proxy events. The method now catches the exception, logs a WARNING with full traceback, and returns an empty historical list — the proxy half of the window still renders.

## Compatibility

Blueprint is pure YAML; no new entities, no changes to existing `unique_id`s, services or bus events. Calendar entity, stable `description` keys and the `ai_decision_calendar_trigger` blueprint all keep their public contract. 437 tests green, `mypy --strict` clean, `ruff` clean, Python 3.14 + HA 2026.10.2.
