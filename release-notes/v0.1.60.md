v0.1.60: adds the Heartbeat gateway to the diagnostics dump. Under the hood the `onekommafive` SDK pin moves to `>=0.4.0,<0.5`.

## Added

**Diagnostics: gateway summary.** The diagnostics download now carries a `system.device_gateways[]` block with `type` (backend, e.g. `GRIDX`), `installer_name` (installing partner) and `installation_date` per Heartbeat gateway. Support requests can triage the installed backend and installer without asking for extra screenshots. IDs, serial numbers and every GridX identifier stay out of the payload by contract.

## Changed

**SDK pin raised to `onekommafive>=0.4.0,<0.5`.** Upstream v0.4.0 migrates the `active-features` endpoint from v1 to v2 (response schema stays identical, so existing feature-flag sensors keep working unchanged) and adds `System.get_device_gateways()`. The gateway accessor drives the two additions above.
