v0.1.60: shows the Heartbeat gateway as its own HA sub-device and adds it to the diagnostics dump. Under the hood the `onekommafive` SDK pin moves to `>=0.4.0,<0.5`.

## Added

**Heartbeat-gateway sub-device.** GRIDX-backend installs now see one sub-device per Heartbeat gateway next to the inverter, heat pump, meter and wallbox devices. It carries `1KOMMA5°` as manufacturer, the backend `type` (typically `GRIDX`) as model and the installation date as software version. 1K5-backend installs have no gateway registered and stay unchanged. Multi-gateway installs get one instance sub-device per gateway, labelled with the installing partner name so they stay distinguishable in the HA devices view.

**Diagnostics: gateway summary.** The diagnostics download now carries a `system.device_gateways[]` block with `type`, `installer_name` and `installation_date` per gateway. Support requests can triage the installed backend and installer without asking for extra screenshots. IDs, serial numbers and every GridX identifier stay out of the payload by contract.

## Changed

**SDK pin raised to `onekommafive>=0.4.0,<0.5`.** Upstream v0.4.0 migrates the `active-features` endpoint from v1 to v2 (response schema stays identical, so existing feature-flag sensors keep working unchanged) and adds `System.get_device_gateways()`. The gateway accessor drives the two additions above.
